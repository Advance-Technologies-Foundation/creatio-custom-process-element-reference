# Custom Creatio business process element

Two working references: **Format text** and **Arithmetic**. Arithmetic has four separate user tasks and four distinct parameter pages behind one toolbox entry. Both use app DI, ErrorOr, explicit parameter directions, and error outputs.

Start with [the complete authoring guide](docs/create-custom-business-process-element.md). [The lab record](docs/lab-record.md) separates verified behavior, source research, and known limits.

## Verified result

On Creatio **10.1.585.0 / .NET 8 / PostgreSQL**, the element appears under **User actions**. Its panel accepts a literal prefix and a process-parameter mapping. Both survive saving and reopening. The real engine trims the input and returns the prefixed output. The combined examples currently pass 27 unit cases and 10 live process cases.

The text process exposes Text and Prefix inputs plus FormattedText, IsError and ErrorMessage outputs. Blank input returns a handled validation error. See [the arithmetic reference](docs/arithmetic-element.md) for the four-operation family and its testing boundary.

## Run the examples

Install the package into your own registered, licensed Creatio environment. Open Process library and select **Format text reference** or **Arithmetic operation selector**. The four arithmetic acceptance processes expose both inputs and all three outputs; the selector demonstration has no downstream mappings so operations can be replaced safely.

For local unit tests, first prepare Creatio's generated schema sources and matching `.application` dependencies using the source-development flow below. Restore the unit-test `Libs` from Clio's `new-test-project` scaffold for the matching platform; proprietary test/platform binaries are not distributed here. See Clio's `integration-testing` guidance for test setup.

```powershell
pwsh ./scripts/Test-Reference.ps1 -EnvironmentName <registered-environment>
```

The runner reads credentials privately from your local Clio registration. Integration tests execute the installed processes and do not create business records.

Run `pwsh ./scripts/Test-PackageContract.ps1` without an environment or proprietary
binaries to verify every exported task's explicit directions and error-output types.
The normal test runner and GitHub CI include this check. Version 0.2.0 corrects the
v0.1.0 text-task export, which omitted directions for Text, Prefix and FormattedText;
their schema and parameter identities remain unchanged.

## Install on another compatible environment

Use a fresh development environment with `CrtProcessDesigner` available. PostgreSQL is verified. Arithmetic also includes an authored MSSQL registration script, but SQL Server installation is not validated.

```powershell
clio compress ./packages/UsrCustomProcessElement -d ./artifacts/UsrCustomProcessElement.gz
clio push-pkg ./artifacts/UsrCustomProcessElement.gz -e <target>
```

The normal package installer builds the configuration and restarts the application. Version 0.1.0 installed successfully on a fresh, non-FSM instance without installing ClioGate or issuing a separate compile command; version 0.2.0 was validated as an upgrade on that retained instance. Open a fresh designer session afterward. The package's after-package SQL creates the toolbox entries. Do not run a manual database INSERT as an extra installation step. See [installation evidence](docs/clean-install-verification.md).

For source development, create/register an exclusive environment, enable file-system development, and link the package:

```powershell
clio turn-fsm on -e <target>
clio link-from-repository -e <target> --repoPath . --packages UsrCustomProcessElement --skip-preparation
clio pkg-to-db -e <target>
clio generate-source-code -e <target>
clio compile-configuration -e <target> --all
clio download-configuration -e <target>
```

If FSM changes require a restart, allow it to complete before synchronization. Native generation/compilation supplies the task's partial class under `Autogenerated`; that generated source and local platform dependencies are intentionally ignored by Git. After editing in the browser, run `clio pkg-to-file-system -e <target>` **before** the next `pkg-to-db`, so local files do not overwrite browser changes.

`CrtProcessBuilder` was used to author and inspect the acceptance process via clio MCP. It is a lab tool, not a dependency of the custom task. The exported process already ships in this package. `assets/reference-process.json` records the initial fixture; the current saved text process exposes Prefix explicitly.

## Boundaries

Validated for BPMN, synchronous execution, English captions, text and numeric parameters, PostgreSQL, and the stated Creatio build, including installation into a second fresh environment with FSM off. DCM, interactive waiting/resume, other database engines, older releases, and localized toolbox captions require separate validation.

This repository publishes the reusable snapshot of the tested lab. It does not redistribute Creatio platform assemblies, local environment settings, or investigative logs. See [verification](docs/clean-install-verification.md) and [third-party notices](THIRD-PARTY-NOTICES.md).
